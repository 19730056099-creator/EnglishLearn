# 意群看不懂怎么办

> 背景：已经养成了按意群顺着读的习惯，现在卡住的不是"怎么读"，而是**某一块本身看不懂**。这是下一阶段的正常问题。关于意群本身，见 [[词块/英语词块总览#七、意群（sense group）|意群]]。

例子：`it is fairly awkward to use`（CS61B 里评价 IntList 的一句）。每个单词都认识，难在两个地方：awkward 的感觉对不上中文，`awkward to use` 的结构也不熟。

---

## 一、意群看不懂的五种原因

### 1. 单词的意思和中文对不上
awkward 词典译为"笨拙的、尴尬的"，但"IntList 很尴尬"说不通。中文里没有词正好对应它的核心感觉：**别扭、不顺**。

这类词在 CS 文章里特别多，词典给的中文都不太对味：
awkward、subtle、elegant、straightforward、arbitrary、robust……

### 2. 结构是英语特有的
`awkward to use` 这种 **形容词 + to do**，主语其实是动作的**对象**（是"你用它"，不是"它去用"）。不熟悉就会觉得别扭。

类似结构：
- The code is worth reading.（这代码值得读）
- This bug is hard to reproduce.（这个 bug 很难复现）

### 3. 抽象名词把意思包起来了
the fact that、the idea that、the notion of……英语爱用名词装下一整个意思，中文更习惯直接说。读到时要在心里**拆开**。

### 4. 代词指什么不清楚
it、this、which 指代前文的什么，有时要回头去找。

### 5. 习语或文化背景
比如 [[短语/in the redblue corner|in the red corner]]，不知道拳击背景就猜不出来。

---

## 二、遇到看不懂的意群怎么办

1. **先判断是哪一种原因。** 这一步本身就很有用，慢慢会发现自己总卡在同一两类上。
2. **查英英词典，不查英汉词典。** 英汉词典只给几个中文词，你还是不知道选哪个。英英学习词典（Longman、Cambridge 在线版）用简单英语解释，还按用法分开：
   > awkward: difficult to use or deal with（难以使用或处理的）

   一看就知道这里是哪个意思。
3. **看上下文对应关系。** 作者经常自己解释。例句里，前面说 technically 能做所有事，后面说 `resulting in code that is hard to read`，夹在中间的 awkward 基本就能推出来。
4. **还是不懂，就拿来问。** 把句子发出来，让母语者视角讲清楚它是什么感觉。问一次，就搞懂一整类结构，比硬猜效率高。

## 三、换个角度：卡住的地方最值得积累

这些卡住的意群，**正是中文思维和英文思维不一样的地方**。顺利读懂的部分说明已经会了，卡住的才是要补的。所以遇到就记进笔记，价值最高。

---

## 四、阅读量够了为什么还卡？

### 阅读量确实是最大的因素
awkward 这种词，母语者从小在各种场景见过几百次：awkward silence、awkward moment、awkward to use、an awkward position……见多了，脑子里自然形成"别扭、不顺"的感觉，根本不需要定义。

如果只在词典或孤立句子里见过几次，感觉就建立不起来。这只能靠多读来补，没有捷径。

### 但光读多也不够
很多人读了很多英文，还是一直卡在同类问题上，因为遇到不懂的块**大概猜个意思就跳过**，下次再见还是模糊。读得多，但没有真正"注意"到它。

所以阅读分两种：

| | 泛读 | 精读 |
|---|---|---|
| 量 | 大 | 小（一天几个就够） |
| 速度 | 快，不求全懂 | 停下来，弄透 |
| 材料 | 难度适中、感兴趣的：技术博客、Reddit 编程讨论、英文新闻 | 读 CS61B 时卡住的块 |
| 做法 | 能猜就猜，别停 | 搞清楚为什么是这个意思，记下来 |
| 作用 | 让常见表达反复出现，积累"感觉" | 见了就记住 |

泛读负责"见得多"，精读负责"见了就记住"，两个配合提升更快。

### 判断我现在的阶段
已经不看主谓宾、能按意群读，说明基础阅读量不算小。现在卡住的主要是**少数特定的词和结构**。这个阶段单纯加大阅读量，效果会慢慢变弱，**有意识地精读卡住的地方**反而更关键。

所以："遇到一句不懂，拿出来问清楚"正是现在最该做的事。同时平时多泛读，把量也慢慢堆上去。
